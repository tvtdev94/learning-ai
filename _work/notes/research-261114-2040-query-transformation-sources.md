# Research notes: query-transformation (2026-11-14)

Format: khẳng định → URL → câu trích ngắn (đã mở bằng WebFetch ngày 2026-11-14).

- [1] Survey RAG chia Naive / Advanced / Modular RAG → https://arxiv.org/abs/2312.10997 → "encompassing the Naive RAG, the Advanced RAG, and the Modular RAG"
- [2] Rewrite-Retrieve-Read: viết lại truy vấn trước khi tìm, vì input và kiến thức cần tìm không luôn khớp; có bản rewriter nhỏ huấn luyện bằng RL → https://arxiv.org/abs/2305.14283 → "a new framework, Rewrite-Retrieve-Read instead of the previous retrieve-then-read"; "A small language model is adopted as a trainable rewriter"
- [3] Câu hỏi trong hội thoại phụ thuộc ngữ cảnh; viết lại thành câu độc lập cùng đáp án; CANARD 40.527 câu → https://aclanthology.org/D19-1605/ → "rewrite a context-dependent into a self-contained question with the same answer"
- [4] LangChain history-aware retriever: không có lịch sử thì chuyển thẳng input; có lịch sử thì LLM sinh search query → https://reference.langchain.com/python/langchain-classic/chains/history_aware_retriever/create_history_aware_retriever → "If there is no `chat_history`, then the `input` is just passed directly to the retriever."
- [5] MultiQueryRetriever: LLM viết nhiều truy vấn, tìm cho từng truy vấn, trả unique union → https://reference.langchain.com/python/langchain-classic/retrievers/multi_query/MultiQueryRetriever → "Given a query, use an LLM to write a set of queries. Retrieve docs for each query. Return the unique union"
- [6] RAG-Fusion: nhiều truy vấn + reciprocal rank fusion; có câu trả lời lạc đề khi truy vấn sinh ra kém liên quan → https://arxiv.org/abs/2402.03367 → "some answers strayed off topic when the generated queries' relevance to the original query is insufficient"
- [7] RRF: score += 1/(k + rank), rank từ 1, rank_constant mặc định 60 → https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion → "score += 1.0 / ( k + rank( result(q), d ) )"; "Defaults to `60`"
- [8] Least-to-most: tách bài toán phức tạp thành chuỗi bài con, giải tuần tự, đáp án trước giúp bài sau → https://arxiv.org/abs/2205.10625 → "to break down a complex problem into a series of simpler subproblems and then solve them in sequence"
- [9] Self-ask: model tự hỏi và trả lời câu hỏi phụ; cắm search engine trả lời câu hỏi phụ → https://arxiv.org/abs/2210.03350 → "self-ask's structured prompting lets us easily plug in a search engine to answer the follow-up questions"
- [10] LlamaIndex query transformations: HyDE sinh tài liệu/đáp án giả định dùng để embed thay câu gốc; multi-step decomposition sinh câu hỏi tiếp theo từ câu gốc + câu trả lời trước → https://developers.llamaindex.ai/python/framework/optimizing/advanced_retrieval/query_transformations/ → "This hypothetical document is then used for embedding lookup rather than the raw query."
- [11] SubQuestionQueryEngine: tách câu hỏi phức tạp thành câu hỏi con cho từng nguồn, gom câu trả lời trung gian rồi tổng hợp → https://developers.llamaindex.ai/python/examples/query_engine/sub_question_query_engine/ → "breaks down the complex query into sub questions for each relevant data source"
- [12] Step-back prompting: trừu tượng hóa thành khái niệm cấp cao; PaLM-2L +7%/+11% MMLU Physics/Chemistry, +27% TimeQA, +7% MuSiQue; dùng RAG truy xuất cả câu gốc và câu step-back; ví dụ Estella Leopold → https://arxiv.org/abs/2310.06117 , https://arxiv.org/html/2310.06117 → "The step-back question is used to retrieve relevant facts, which work as additional context"; "Using both the retrieval augmentations from the original question and the step-back question"
- [13] HyDE: LLM sinh tài liệu giả định (có thể chứa chi tiết sai), encoder embed, tìm tài liệu thật gần đó; zero-shot không cần nhãn → https://arxiv.org/abs/2212.10496 → "captures relevance patterns but is unreal and may contain false details"; "dense bottleneck filtering out the incorrect details"
- [14] Query2doc: sinh pseudo-document bằng few-shot rồi ghép vào truy vấn; BM25 +3% đến 15% trên MS-MARCO, TREC DL → https://arxiv.org/abs/2303.07678 → "a simple yet effective query expansion approach"
- [15] LlamaIndex routers: chọn một hoặc nhiều lựa chọn (nguồn dữ liệu, query engine, retriever) bằng LLM; selector LLM hoặc Pydantic (function calling); single/multi → https://developers.llamaindex.ai/python/framework/module_guides/querying/router/ → "Selecting the right data source among a diverse range of data sources"
- [16] Adaptive-RAG: classifier nhỏ đoán độ phức tạp; câu đơn giản không cần xử lý nhiều bước; tăng hiệu quả và độ chính xác → https://arxiv.org/abs/2403.14403 → "handle simple queries with unnecessary computational overhead"
- [17] LangChain SelfQueryRetriever: dùng vector store + LLM để sinh truy vấn cho vector store → https://reference.langchain.com/python/langchain-classic/retrievers/self_query/base/SelfQueryRetriever → "Retriever that uses a vector store and an LLM to generate the vector store queries."
- [18] Elastic: self-querying retriever, LLM trích filter từ câu hỏi, kết hợp semantic search + metadata filter; ví dụ phim sci-fi sau 2000 rating > 8 → https://www.elastic.co/search-labs/blog/self-querying-retrievers → "the query is parsed by the LLM to extract filters from the natural language query"
- [19] LlamaIndex auto-retrieval: LLM suy ra metadata filters và query string, mỗi cái có thể rỗng → https://developers.llamaindex.ai/python/examples/vector_stores/elasticsearch_auto_retriever/ → "infer a set of metadata filters as well as the right query string to pass to the vector db"
- [20] Query expansion: người dùng không luôn dùng từ tốt nhất; sửa chính tả, đồng nghĩa; tăng recall đổi lấy precision → https://en.wikipedia.org/wiki/Query_expansion → "users do not always formulate search queries using the best terms"; "the recall is also increased at the expense of precision"
- [21] Recall, P@k định nghĩa → https://en.wikipedia.org/wiki/Evaluation_measures_(information_retrieval) → "Recall is the fraction of the documents that are relevant to the query that are successfully retrieved."
- [22] MRR = trung bình nghịch đảo hạng của kết quả đúng đầu tiên; không có thì 0 → https://en.wikipedia.org/wiki/Mean_reciprocal_rank → "the multiplicative inverse of the rank of the first correct answer"
- [23] Ragas context recall: đo bao nhiêu thông tin liên quan được tìm thấy, luôn cần reference → https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/ → "calculating context recall always requires a reference to compare against"

## Ghi chú suy luận (không có nguồn trực tiếp, trang viết thận trọng/ghi "minh họa")
- Độ trễ, số lượt gọi trong máy tính là mô hình đơn giản do trang tự đặt; tham số do người đọc chỉnh; ghi rõ "minh họa".
- "Mỗi kỹ thuật thêm ít nhất một lượt gọi LLM trước khi tìm" suy ra từ mô tả phương pháp ở [2][5][10][13][15][17].
- Mọi câu hỏi mẫu và câu truy vấn biến đổi trong demo là minh họa do trang viết tay, không phải đầu ra model.
