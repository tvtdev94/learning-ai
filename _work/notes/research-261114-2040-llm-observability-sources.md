## Nền tảng observability và tracing
- [1] Observability = hiểu hệ thống từ bên ngoài; telemetry gồm traces, metrics, logs; định nghĩa log, metric, distributed trace → https://opentelemetry.io/docs/concepts/observability-primer/ → "Observability lets you understand a system from the outside"; "Telemetry refers to data emitted from a system and its behavior."; "A log is a timestamped message emitted by services or other components."; "Metrics are aggregations over a period of time of numeric data…"; "A distributed trace, more commonly known as a trace, records the path taken by a single request"
- [2] Span là một đơn vị công việc; span lồng nhau qua parent_id; root span không có parent; span context chứa trace ID + span ID; attributes, events, status (Unset/Error/Ok), span kind → https://opentelemetry.io/docs/concepts/signals/traces/ → "A span represents a unit of work or operation."; "Spans can be nested, as is implied by the presence of a parent span ID: child spans represent sub-operations."; "but has no parent_id. That's how you know it's the root span."; "Each span has a status. The three possible values are: Unset, Error, Ok"; "A Span Event can be thought of as a structured log message (or annotation) on a Span"
- [3] W3C Trace Context: header traceparent gồm version, trace-id, parent-id, trace-flags; là W3C Recommendation 23/11/2021 → https://www.w3.org/TR/trace-context/ → "defines standard HTTP headers and a value format to propagate context information"; "It has four fields."; "W3C Recommendation 23 November 2021"
- [4] Sampling giảm chi phí; head sampling quyết định sớm; tail sampling xét cả trace; tail có thể giữ mọi trace lỗi / theo latency; head sampling không đảm bảo giữ trace lỗi → https://opentelemetry.io/docs/concepts/sampling/ → "Sampling is one of the most effective ways to reduce the costs of observability without losing visibility."; "Always sampling traces that contain an error"; "Sampling traces based on overall latency"; "you cannot ensure that all traces with an error within them are sampled with head sampling alone."

## OpenTelemetry GenAI semantic conventions (trạng thái đúng như trang đã mở)
- [5] Trang GenAI trên opentelemetry.io đã ghi "Moved", chuyển sang repo semantic-conventions-genai, không còn được duy trì ở đó; trang không ghi mức ổn định → https://opentelemetry.io/docs/specs/semconv/gen-ai/ → "GenAI semantic conventions have moved to the OpenTelemetry GenAI semantic conventions repository"; "This page has moved and is no longer maintained in this repository."
- [6] Repo mới: quy ước cho spans, metrics, events của GenAI client, MCP, quy ước riêng nhà cung cấp; README không ghi mức ổn định → https://github.com/open-telemetry/semantic-conventions-genai → "Semantic Conventions for Generative AI (GenAI), including spans, metrics, and events for GenAI clients"
- [7] docs/gen-ai/README.md: Status: Development; liệt kê Model spans, Agent spans, Events, Metrics, Exceptions, Client Inference, Execute Tool, Retrieval… → https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/README.md → "Status: Development"
- [8] Client inference span: tên `{gen_ai.operation.name} {gen_ai.request.model}`; kind CLIENT; thuộc tính gen_ai.operation.name (Required), gen_ai.provider.name (Required), gen_ai.request.model (Conditionally Required), gen_ai.request.temperature, gen_ai.request.max_tokens, gen_ai.usage.input_tokens, gen_ai.usage.output_tokens, gen_ai.response.finish_reasons (Recommended), error.type (Conditionally Required), gen_ai.input.messages / gen_ai.output.messages (Opt-In), gen_ai.conversation.id; metric gen_ai.client.inference.duration, gen_ai.client.inference.time_to_first_chunk; Status Development → https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/client-inference.md → "Span name SHOULD be {gen_ai.operation.name} {gen_ai.request.model}."; "The number of input tokens reported by the provider for this inference operation."
- [9] Nội dung (instructions, input, output) nhạy cảm, mặc định KHÔNG ghi, cần opt-in; biến môi trường OTEL_INSTRUMENTATION_GENAI_CAPTURE_CONTENT, mặc định NO_CONTENT → https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/gen-ai-spans.md → "Model instructions, user messages, and model outputs are considered sensitive and are often large in size."; "OpenTelemetry instrumentations SHOULD NOT capture them by default, but SHOULD provide an option for users to opt in."; "NO_CONTENT | Do not capture content on spans or events. (Default)"
- [10] Retrieval span: operation `retrieval`, kind INTERNAL, gen_ai.retrieval.top_k (Recommended), gen_ai.retrieval.documents (id, score) và gen_ai.retrieval.query.text là Opt-In → https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/retrieval.md → "The documents retrieved."; "This attribute may contain sensitive information."
- [11] Execute tool span: tên `execute_tool {gen_ai.tool.name}`, kind INTERNAL; gen_ai.tool.name Required; arguments/result Opt-In → https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/execute-tool.md → "Span name SHOULD be execute_tool {gen_ai.tool.name}."
- [12] Agent span: operation invoke_agent, tên `invoke_agent {gen_ai.agent.name}`, kind INTERNAL; create_agent → https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/gen-ai-agent-spans.md → "Span name SHOULD be {gen_ai.operation.name} {gen_ai.agent.name}"
- [13] Event gen_ai.evaluation.result: gắn (parent) vào span đang được chấm; thuộc tính gen_ai.evaluation.name, score.value, score.label, explanation → https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/main/docs/gen-ai/gen-ai-events.md → "This event SHOULD be parented to GenAI operation span being evaluated when possible"

## Công cụ (Langfuse, OpenInference)
- [14] LLM không tất định → debug không có observability là đoán; trace ghi prompt, response, token, latency, tool/retrieval; cho eval chạy trên trace thật → https://langfuse.com/docs/observability/overview → "Generative AI systems are inherently non-deterministic."; "debugging your application without any observability tool is more like guesswork."; "capture the exact prompt sent, the model's response, token usage, latency"
- [15] Trace = một request; observation = từng bước, lồng nhau; session gom nhiều trace (ví dụ một thread chat); user_id → https://langfuse.com/docs/observability/data-model → "A trace represents a single request or operation"; "Sessions are used to group traces that are part of the same user interaction."
- [16] Loại observation: event, span, generation, agent, tool, chain, retriever, evaluator, embedding, guardrail → https://langfuse.com/docs/observability/features/observation-types → "logs generations of AI models incl. prompts, token usage and costs"
- [17] Chi phí: ingested hoặc inferred (usage × giá model); ingested ưu tiên; không còn tự ước lượng token; bucket chồng lấn → đếm đôi → https://langfuse.com/docs/observability/features/token-and-cost-tracking → "Langfuse then multiplies those prices by the observation's usage to calculate cost."; "If buckets overlap, usage and inferred cost will be counted double."
- [18] Phản hồi explicit (thumbs, sao) hiếm và lệch về người không hài lòng; implicit (thử lại, sửa bản nháp); mọi tín hiệu thành score trên trace; lọc trace điểm thấp; thêm ca lỗi vào dataset; biến lỗi lặp lại thành evaluator tự động → https://langfuse.com/guides/user-feedback-loop → "unambiguous, but rare and skewed toward unhappy users"; "Every signal ends up as a score on the trace that produced the output."; "Add the failing cases to a dataset, test a fix with an experiment before shipping"
- [19] Masking: che dữ liệu nhạy cảm trước khi rời ứng dụng; ví dụ email, thẻ tín dụng → https://langfuse.com/docs/observability/features/masking → "Use masking functions to redact sensitive information before trace data leaves your application"
- [20] Retention: cấu hình theo project, số ngày, tối thiểu 3 ngày; xóa hằng đêm; không khôi phục được → https://langfuse.com/docs/administration/data-retention → "Data retention is configured on a project level, and we accept a number of days with a minimum of 3 days."; "Deleted assets cannot be recovered."
- [21] OpenInference: bộ quy ước + plugin bổ trợ cho OpenTelemetry; dùng được với backend tương thích OTel → https://github.com/Arize-ai/openinference → "a set of conventions and plugins that is complementary to OpenTelemetry to enable tracing of AI applications"

## Vì sao khó debug, latency, quyền riêng tư, eval
- [22] Kể cả temperature 0 kết quả vẫn không hoàn toàn tất định; định nghĩa TTFT → https://platform.claude.com/docs/en/about-claude/glossary → "Even with temperature set to 0, the results will not be fully deterministic"
- [23] Agent: chi phí cao hơn, lỗi có thể dồn; ưu tiên minh bạch các bước → https://www.anthropic.com/engineering/building-effective-agents → "The autonomous nature of agents means higher costs, and the potential for compounding errors."
- [24] Bốn tín hiệu vàng; lỗi ngầm (200 nhưng nội dung sai); mean gây hiểu nhầm, dùng percentile/histogram; tách latency của request lỗi → https://sre.google/sre-book/monitoring-distributed-systems/ → "The rate of requests that fail."; "1% of requests might easily take 5 seconds."; "It's important to distinguish between the latency of successful requests and the latency of failed requests."
- [25] GDPR Điều 5(1)(c) tối thiểu hóa dữ liệu, 5(1)(e) giới hạn lưu trữ → https://gdpr-info.eu/art-5-gdpr/ → "limited to what is necessary in relation to the purposes"; "for no longer than is necessary for the purposes"
- [26] Luật Bảo vệ dữ liệu cá nhân số 91/2025/QH15, ban hành 26/06/2025, hiệu lực 01/01/2026 (chỉ dẫn tên và ngày; nội dung điều khoản chưa đọc) → https://congbao.chinhphu.vn/van-ban/luat-so-91-2025-qh15-45578.htm → "Luật số 91/2025/QH15 luật Bảo vệ dữ liệu cá nhân."; "01/01/2026"
- [27] Presidio phát hiện/ẩn danh PII; không đảm bảo tìm hết → https://presidio.dataprivacystack.org/ → "there is no guarantee that Presidio will find all sensitive information."
- [28] Ghi trace là điều kiện tiên quyết cho eval; đọc trace; cập nhật test từ lỗi mới → https://hamel.dev/blog/posts/evals/ → "A prerequisite to performing human and model-based eval is to log your traces."; "We continuously update them based on new failures we observe in the data"
